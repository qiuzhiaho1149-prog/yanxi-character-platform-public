# 09 · 开源发布与脱敏

> 这个仓库会开源。本文规定：发布什么、不发布什么、怎么脱敏、历史怎么处理。

## 1. 发布范围

### 会发布

```text
README.md / SECURITY.md / CONTRIBUTING.md / LICENSE / AGENTS.md / .env.example
项目/               当前权威文档（占位符版）
packs/              Character Pack 示例（占位符版）
插件/               角色引擎与生活/视觉插件
部署/cloud-patches/ 补丁 overlay、sidecar、profile 模板（占位符）
部署/migrate-character-data.sh
人设/               可公开的人设与资料
scripts/            脱敏检查、公开导出
```

### 不发布

```text
部署/private/       真实实例值（QQ、IP、账号、路径）
backups/            运行备份
归档/               旧角色归档
repos/              上游仓库快照
研究-系统状态/      含会话/证据/个人上下文的实验记录
research/           旧研究草稿（按需决定）
验证截图/
.env / *.env / *.local.md
events.jsonl / owner.json / session 数据
```

## 3. 自动脱敏检查

```bash
scripts/check-sensitive.sh --staged
```

- 已配置 `.githooks/pre-commit`
- 新克隆后执行：
  ```bash
  git config core.hooksPath .githooks
  ```
- 检查：API key、cookie、私钥、真实 QQ/群号、服务器 IP、个人路径、GitHub 账号
- 发现即拒绝提交；例外只在检查脚本和安全文档的规则示例里

## 4. 开源前必须做（重要）

### 4.1 当前文件已脱敏 ≠ 历史已脱敏

Git 历史里仍然可能有旧 QQ 号、IP、路径、cookie。**直接把当前私有仓库改成 public 会泄露历史。**

二选一：

1. 新建一个干净仓库，只推送脱敏快照（推荐，最稳）
2. 用 `git filter-repo` 重写历史，再 force push

### 4.2 用公开快照脚本

```bash
scripts/export-public.sh /tmp/yanxi-public
cd /tmp/yanxi-public
git init -b main
git add -A
git commit -m "initial public release"
```

脚本只复制白名单路径，不包含备份/私密部署/研究会话。

### 4.3 素材授权

代码 MIT，但以下素材授权需单独确认：

- 嫣汐角色名/形象
- 音色克隆的参考音频
- 立绘、头像、歌词、曲目
- 第三方插件源码/素材

没有授权的素材不要放进公开 Character Pack；在 `NOTICE`/`ASSETS` 里写清楚。

### 4.4 密钥轮换

任何曾经在聊天、日志、测试文件、Git 历史里出现过的 key/token/cookie，在公开前轮换，不要只删文件。

## 5. 实例与仓库的关系

- 私有云端实例：可以使用真实值，但只放在 `/etc/dsh-yanxi.env`、`部署/private/`、运行时数据目录
- 公开仓库：只保留模板和占位符
- 云端手动改动：同步到 `部署/cloud-patches/`，不把服务器当唯一副本

## 6. 发布检查清单

- [ ] `scripts/check-sensitive.sh` 通过
- [ ] 公开快照只含白名单路径
- [ ] Git 历史已重写或使用全新仓库
- [ ] key/token/cookie 已轮换（如曾泄露）
- [ ] 角色/音色/素材授权确认
- [ ] README 里没有实例真实值
- [ ] `部署/private/` 未被提交
- [ ] 没有会话/日记/事件流/截图
- [ ] CI/测试可运行
- [ ] 许可证与第三方 NOTICE 完整
