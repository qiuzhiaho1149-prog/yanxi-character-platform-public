# 08 · 云端多角色、热插拔与隔离架构

> 背景：这个项目不是单一 QQ 机器人，而是基于开源生态逐步增强的**完整人格系统**。最终要能云端部署、角色热插拔、角色隔离，并复用到更广泛的产品。

## 1. 目标形态

```text
                    ┌────────────────────────────┐
                    │  Gateway / Router           │
                    │  账号→角色映射、鉴权、健康   │
                    └────────────┬───────────────┘
                                 │
        ┌────────────────────────┼────────────────────────┐
        │                        │                        │
┌───────▼────────┐      ┌────────▼───────┐      ┌────────▼───────┐
│ CharacterRuntime│      │ CharacterRuntime│      │ CharacterRuntime│
│ 嫣汐 worker     │      │ 阿哲 worker     │      │ 其他角色 worker  │
│ 独立数据/工具/配额│      │ 独立数据/工具/配额│      │ 独立数据/工具/配额│
└───────┬────────┘      └────────┬───────┘      └────────┬───────┘
        │                        │                        │
        └────────────┬───────────┴────────────┬───────────┘
                     │                        │
          ┌──────────▼─────────┐    ┌─────────▼──────────┐
          │ 角色包注册表         │    │ 共享基础设施         │
          │ Character Packs     │    │ 模型代理/日志/备份   │
          └────────────────────┘    └────────────────────┘
```

### 关键原则

- **一个角色 = 一个隔离运行时**；不是所有角色共用一个 Agent 进程。
- **一个 QQ 号只绑一个角色**；多角色用多个账号/窗口。
- **角色包只读**，运行数据写角色自己的数据卷。
- **Gateway 负责路由**，角色运行时不知道其他角色存在。
- **热插拔**是“启动/停止/重载一个角色 worker + 改绑定”，不是“在同一个 Agent 里换 prompt”。

## 2. 角色包（Character Pack）

```text
packs/yanxi/
  character.json        # id/name/version/entry
  seed.md               # 人设种子
  behavior.md           # 正向行为/说话方式
  assets/               # 头像、音色、参考音频
  tools.json            # 允许的能力/工具
  windows.json          # 绑定窗口/账号
  social.json           # 初始关系/隐私
  migrations/           # 数据版本迁移
```

### 热插拔要求

- 包有版本号；启动时校验 manifest
- 角色数据独立卷：`/var/lib/yanxi/characters/<id>/`
- 启动：创建/恢复数据 → 加载事件流 → 启动窗口 → 健康检查
- 停止：停止接收新事件 → drain 当前回合 → 落盘 → 释放窗口
- 重载：停止 → 替换包版本 → 启动；失败回滚上一版
- 切换绑定：账号 A 从角色 1 切到角色 2，必须先 drain，不迁移记忆
- 配额：每角色每日消息/模型 token/语音时长独立计数

## 3. 隔离维度

| 维度 | 要求 |
| --- | --- |
| 数据 | 独立根目录、事件流、日记、媒体、记忆；不跨角色读写 |
| 身份 | 独立 seed/behavior/prompt；不共享人格状态 |
| 工具 | 每个运行时独立注册/限制；不暴露宿主 |
| 社交 | 独立好友/群/关系/owner |
| 窗口 | 独立 QQ 账号/NapCat；Gateway 映射 |
| 密钥 | 每角色独立 env/secret，最小权限 |
| 配额 | 消息、token、语音、B站次数独立 |
| 故障 | 一个角色崩溃/重启不影响其他角色 |
| 观测 | 每角色独立日志/指标/审计 |

## 4. 云端部署形态

### 推荐：Gateway + 每角色一个 Worker

- Gateway：Node 服务，维护账号→角色、健康检查、管理 API、配额
- Character Worker：一个角色一个进程/容器，DSH 或后续 Kernel 运行时
- Window Adapter：每个 QQ 号一个 NapCat 容器；B站/本地同理
- 存储：每角色独立 Docker volume；共享只读包注册表
- 反向代理：只暴露 Gateway/管理入口，DSH/NapCat 不暴露公网
- 密钥：Docker secrets / systemd EnvironmentFile，600
- 备份：每角色数据卷 + 包版本 + 配置
- 观测：每角色日志、健康、预算、崩溃重启

### 自托管单机（当前过渡）

- Docker Compose 或 systemd
- 先只跑一个嫣汐 worker
- Gateway 可以先是一个轻量路由 + 管理脚本
- 不要把所有角色塞进同一个 DSH profile

### 云 SaaS（后续）

- 每角色容器隔离；按角色/租户计费
- 资源配额、限流、审计
- 数据导出/删除/迁移
- 不做多角色同 QQ 号

## 6. 迁移路线（不改行为优先）

### Step 0：冻结与备份
- 冻结当前云端行为
- 备份 `~/.dsh-yanxi`、profile、NapCat 配置
- 把云端补丁入仓

### Step 1：Pack 化嫣汐（不重写 Kernel）
- 建 `packs/yanxi/`：manifest/seed/behavior/tools/windows/social
- 当前 `dsh-yanxi` 仍跑，但配置从 pack 读取
- 数据根迁移到 `/var/lib/yanxi/characters/yanxi/`
- 单角色行为不变；有回归测试

### Step 2：Gateway 单角色
- 账号→yanxi 映射
- 健康检查、管理 API、预算/日志
- NapCat/DSH 不暴露公网

### Step 3：每角色 worker
- 抽 supervisor；启动/停止/健康
- 当前嫣汐迁移到独立 worker
- 行为不回退

### Step 4：第二角色
- 阿哲/嫣汐 2 pack
- 独立 QQ/窗口
- 隔离测试：数据/工具/社交/窗口/故障

### Step 5：热插拔
- 启动/停止/重载/回滚
- 切换窗口绑定（drain）
- 配额与观测

## 7. 接口草案

```ts
interface CharacterManager {
  list(): CharacterInfo[]
  start(id: string, packVersion: string): Promise<RuntimeHandle>
  stop(id: string, opts: { drain: true }): Promise<void>
  reload(id: string, packVersion: string): Promise<void>
  bindWindow(windowId: string, characterId: string): Promise<void>
}

interface RuntimeHandle {
  id: string
  status: 'starting' | 'healthy' | 'draining' | 'stopped' | 'failed'
  dataRoot: string
  health(): Promise<Health>
}
```

## 8. 关键风险

- DSH 当前插件生命周期是否支持干净卸载/重载；需先做实验
- 每角色一个进程会增加内存/启动开销；4C8G 只能跑少量角色
- 一个 QQ 号只能绑一个角色；多角色要多账号
- 角色包与事件流迁移需要版本兼容
- 云端密钥/账号隔离必须代码级，不靠约定
- 热插拔窗口会导致短暂不可用；要 drain 和健康检查

## 9. 优先级
