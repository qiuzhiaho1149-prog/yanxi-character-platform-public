# 嫣汐项目 · 统一入口

> 这份文档是项目的唯一入口。以后任何 Agent 接手，先读这里，再读 `项目/` 下的指定文档。
> 旧的大肥鱼文档、研究记录、临时方案保留，但状态在 [`文档索引.md`](文档索引.md) 里标明。

## 一句话

**做一个开源的角色成长平台：Kernel 负责“怎么活”，Character Pack 负责“谁在活”，窗口负责“在哪里活”。嫣汐是第一个跑通实验的角色。**

## 三个原则

| 原则 | 含义 | 检查问题 |
| --- | --- | --- |
| 高度 | 先定顶层不变量，再做局部实现 | 这个改动是否让 Kernel / Character Pack / Window 的边界更清楚？ |
| 深度 | 关键链路要有真实证据，不靠猜 | 是否有云端/端到端/失败路径的验证？ |
| 广度 | 为第二角色、第二窗口、开源扩展留接口 | 换角色、换平台、加能力时是否需要重写？ |

## 当前阶段

**Phase 0：嫣汐实验版稳定运行。**

已有一个可用的云端 QQ 窗口、成长引擎、语音/图片/社交基础能力；但还不是开源平台，Kernel 还没抽，部分补丁只存在于云端。

## 最重要的工作纪律

- 先更新计划，再改代码；改完把验证结果写回 `04-当前状态与交接.md`。
- 不把角色专属逻辑写进 Kernel；不把平台逻辑写进 Character Pack。
- 提示词以正向行为为主；负面清单只保留安全/法律/泄露这种硬边界，且尽量放到 guard/输出过滤器，而不是提示词。
- 任何云端手工改动都要同步到项目仓库或记录补丁；否则下次升级会丢。
- 不把密钥、cookie、二维码写进文档。
