# 11 · 音频能力边界与唱歌链路

> 日期：2026-11-06  
> 结论先说：**MiniMax 的“克隆音色”和“唱歌”是两条不同的能力，不能把克隆音色直接接到唱歌上。**

## 1. 官方能力矩阵

| 能力 | 接口 | 是否支持 | 说明 |
| --- | --- | --- | --- |
| 克隆音色说话 | `/v1/voice_clone` + `/v1/t2a_v2` | 支持 | 10s~5min 参考音频；输出 TTS |
| TTS 唱歌 | `/v1/t2a_v2` | **不支持** | 只有说话、停顿、语气词；`(humming)` 只能哼，不按旋律唱 |
| TTS 混响/空间 | `/v1/t2a_v2` `voice_modify` | 有限 | `sound_effects` 仅 4 个，且**没有强度参数**；实测 auditorium 过强 |
| 当前默认 | — | 关闭 | 空间效果默认 `''`；`MINIMAX_ALLOW_STRONG_EFFECTS=1` 才允许 spacious_echo |
| TTS 亮度/力度/厚度 | `voice_modify` | 支持 | `pitch` / `intensity` / `timbre`，范围 -100~100 |
| Music 生成歌曲 | `/v1/music_generation` | 另一条线 | prompt + lyrics，生成完整歌曲；当前账号返回 2153，新用户不可用 |
| Music 选择/克隆音色 | Music Generation | **不支持** | 请求契约没有 `voice` / 参考音频字段；不能把 `yanxiClone04` 塞进去 |
| 自托管 Music3 | SGLang-Omni + `MiniMaxAI/MiniMax-Music3` | 可用但重 | 官方明确：**Voice selection or cloning: Not supported by this request contract** |
| 真实音色唱歌 | MUTA / AISingers / RVC 等 | 需另建链路 | 这才是“嫣汐音色唱歌”的可能路径 |

官方来源：

- TTS：<https://platform.minimax.io/docs/api-reference/speech-t2a-http.md>
- Voice Clone：<https://platform.minimax.io/docs/api-reference/voice-cloning-clone.md>
- Music Generation：<https://platform.minimax.io/docs/api-reference/music-generation.md>
- 自托管 Music3：<https://platform.minimax.io/docs/guides/local-deploy-music-3.md>

## 2. 为什么“克隆声线然后唱歌”不成立

### TTS 的输入不是歌曲
`/v1/t2a_v2` 的 text 是“要念出来的文本”，不是歌词 + 旋律。它不会：
- 识谱
- 生成旋律
- 按节拍唱
- 保持长音/转音

### Music 的输入不是克隆音色
`/v1/music_generation` 的请求体只有：
- `model`
- `prompt`（风格/情绪/场景）
- `lyrics`
- `is_instrumental`
- `audio_setting`

没有 `voice_id`，没有参考音频。官方自托管文档也明确写了：

> Voice selection or cloning — Not supported by this request contract. `voice` and reference-audio fields are rejected.

所以“克隆音色 + 歌词 + 唱歌”不是 MiniMax 当前 API 的一个组合能力。

### 社区常见替代方案
1. **Music 生成一首歌**（或其他来源歌曲）
2. **Demucs 分离人声**
3. **RVC / Applio / Seed-VC 把人声转换成目标音色**
4. 混音导出

这条路能做“像某人的翻唱”，但需要 GPU、训练数据、授权，不是 MiniMax API 直接输出。

## 3. 我们当前的请求结构

```text
QQ 文本
  → 导演 LLM（DeepSeek）
  → 表演计划 JSON
  → 解析器（白名单）
  → minimax_voice.py
  → POST /v1/t2a_v2
  → 可选本地 ambience 混音
```

导演 JSON 目前包含：

```json
{
  "script": "...",
  "emotion": "happy",
  "speed": 1.02,
  "pitch": 1,
  "voiceProfile": "bright",
  "energy": 0.7,
  "intimacy": 0.4,
  "pace": "normal",
  "tags": ["breath"],
  "soundEffect": "auditorium_echo",
  "ambience": "room"
}
```

映射关系：

| 导演字段 | TTS 请求 |
| --- | --- |
| script | `text` |
| emotion | `voice_setting.emotion` |
| speed / pitch | `voice_setting.speed / pitch` |
| voiceProfile | 选 `voice_id` |
| soundEffect | `voice_modify.sound_effects` |
| energy / intimacy | `voice_modify.intensity / timbre` |
| tags | 必须已经写进 `script`，TTS 才生效 |
| ambience | 不进 TTS；本地 ffmpeg 混音 |

## 4. 推荐的真实唱歌链路

### 方案 A：MUTA / AISingers（最像嫣汐）
- 嫣汐本身就是 MUTA 声库角色
- 直接输入音高/歌词，得到真正的歌声
- 需要 Windows 声库环境或可调用的合成服务
- 最适合“嫣汐唱歌”这件事

### 方案 B：Music3 + RVC / Seed-VC
- Music3 或别处生成歌
- 人声分离
- RVC/Seed-VC 转成嫣汐音色
- 适合做翻唱、原创曲
- 需要 GPU 和训练/推理环境

### 方案 C：继续用 TTS
- 只能“说”和“哼”
- 适合日常语音、短句、语音消息
- 不适合唱歌

## 5. 项目决策建议

- **日常 QQ 语音**：继续用 TTS + voice profile + 4 个空间效果
- **唱歌**：单独做 `SingingProvider`，不要塞进 `qq_send_voice`
- **场景底音**：本地音频库 / 自托管生成，单独混音
- **不要向用户承诺“克隆音色唱歌”**，除非 MUTA 或 RVC 链路真正跑通

## 6. 接口草案

```ts
type VoiceCapability = 'speak' | 'sing' | 'ambience';

interface VoiceProvider {
  id: 'minimax-tts' | 'muta' | 'rvc' | 'music3';
  supports: VoiceCapability[];
  speak(req: SpeakRequest): Promise<Audio>;
  sing?(req: SingRequest): Promise<Audio>;
  generateAmbience?(req: AmbienceRequest): Promise<Audio>;
}
```

`qq_send_voice` 只调 `speak`；唱歌走独立工具/命令，避免能力混淆。
