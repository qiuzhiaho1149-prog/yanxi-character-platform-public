# 07 · 决策记录（ADR）

> 只记录会反复影响方向的选择。新决策追加，不覆盖旧理由；被推翻时写“替代/失效条件”。

## ADR-001 · 系统定位是角色成长平台，不是 QQ 机器人
- 日期：2026-11-06
- 决策：Kernel / Character Pack / Window 分层；QQ 只是窗口。
- 理由：换角色、换平台、开源都需要。
- 现状：实验版仍在 `dsh-yanxi` fork 中，未抽 Kernel。
- 失效条件：无。

## ADR-002 · 嫣汐是第一个实验角色，不是系统边界
- 日期：2026-11-06
- 决策：不要围绕嫣汐写死 Kernel；未来支持嫣汐 2、阿哲。
- 理由：开源角色平台的前提。
- 现状：`dsh-yanxi` 仍带角色专属命名与工具前缀。

## ADR-003 · QQ 用真号 OneBot，不用官方 bot
- 日期：2026-11-05
- 决策：NapCat + 真 QQ 小号，换取全量群消息、语音、好友/群邀请能力。
- 代价：违反腾讯用户协议，机房 IP 风控，掉线/封号风险。
- 限制：主动加群/加好友仍受协议限制。

## ADR-004 · 一个 QQ 号第一阶段只绑一个角色
- 日期：2026-11-06
- 决策：多角色用多个账号/窗口，不做同号多角色路由。
- 理由：避免人格混乱与记忆串线。

## ADR-005 · 身份默认，不自报、不自证
- 日期：2026-11-06
- 决策：角色知道自己是谁即可；日常不主动报名字/设定；被调侃按人的方式反应。
- 理由：人味来自行为一致性，不来自自我介绍；负向“不要提鱼味”会过拟合。
- 现状：已加入 prompt 原则，仍需清理旧负面 prompt。

## ADR-006 · 提示词正向优先，硬边界交给 guard
- 日期：2026-11-06
- 决策：角色 prompt 写“她怎么反应”；安全/泄露/工具限制用代码 guard 和输出过滤器。
- 理由：负面枚举限制泛化、放大触发词。
- 现状：2026-11-06 已把 QQ 私聊/群 prompt 重构为正向行为描述；旧的负面触发枚举已移除。仍待做：语音 director prompt 的进一步正向化、把安全规则全部下沉到 guard。

## ADR-007 · 语音使用 MiniMax 克隆音色 + 导演层
- 日期：2026-11-06
- 决策：参考音频克隆；导演层生成 spoken script + emotion/speed/pitch；TTS 发 QQ。
- 理由：Edge 固定音色没有角色辨识度；导演层解决捧读。
- 风险：MiniMax 余额、克隆质量依赖参考音频。
- 现状：音色 `yanxiClone02`；导演已接，文案仍在调。

## ADR-008 · 图片用自动视觉描述注入，不依赖 read_image
- 日期：2026-11-06
- 决策：QQ 收到图片后插件直接调 DeepSeek Flash 视觉，把描述拼进消息。
- 理由：宿主 `read_image` 未挂载/被 guard 拦；自动注入更可靠。
- 现状：已实现；真实 QQ 端到端待验证。

## ADR-009 · 群插话必须用 requireMention + 概率，不能用 requireMention=false
- 日期：2026-11-06
- 决策：`requireMention: true` + `groupWakeProbability: 0.05`。
- 理由：插件概率逻辑只在 requireMention=true 时执行；false 会每句都回。
- 现状：已修；待观察。

## ADR-010 · seed 事件不可直接改写
- 日期：2026-11-06
- 决策：当前人设调整靠 prompt 覆盖；要换 seed 只能 reset 或显式授权迁移。
- 理由：事件流只追加是成长引擎诚信基础。
- 代价：云端 seed 与本地人设文件可能不同步；交接必须写明。

## ADR-011 · 云端手工补丁必须入仓
- 日期：2026-11-06
- 决策：`dsh-qq-onebot` 源码修改、owner-gate、预算代理、profile 配置都要同步到仓库或补丁目录。
- 理由：升级/重装会丢；无法重建。
- 状态：待执行，是 Phase 0 收尾项。

## ADR-012 · 角色语音默认 happy，但按场景调整
- 日期：2026-11-06
- 决策：默认 happy / speed 1.02 / pitch 1；只有明显难过/生气/受惊/疲惫才换。
- 理由：用户盲听认为 happy 最像嫣汐；neutral/低 pitch 像大妈/丧。
- 注意：pitch 不能长期过高，用户反馈 +2/+4/+6 偏高；默认 1 待进一步观察。


## ADR-013 · 云端采用 Gateway + 每角色独立 Worker
- 日期：2026-11-06
- 决策：角色不是一个共享 DSH profile 里的多个 prompt，而是独立运行时；Gateway 负责账号→角色映射；一个 QQ 号只绑一个角色。
- 理由：热插拔、隔离、故障域、产品化都需要；避免一个角色崩溃/上下文污染影响其他角色。
- 过渡：当前单角色仍可跑在现有云端；Phase 1.5 先 Pack 化 + Gateway 单角色，Phase 2 再拆 worker。
- 风险：DSH 插件生命周期能否干净卸载需实验；多进程内存开销；QQ 账号数量限制。
- 状态：方案已定，未实施。


## ADR-014 · 错误不外泄，上下文溢出自动换会话
- 日期：2026-11-06
- 决策：provider 原始错误（上下文/token/余额/429/堆栈）绝不发到 QQ；改成自然短句；上下文溢出自动 `manager.reset`。
- 理由：结果调性是产品的一部分；用户看到“maximum context length”等于看到机房。
- 实现：`dsh-qq-onebot/src/outbound.js` + `context-guard.js`，已入 `部署/cloud-patches`。
- 现状：已部署；触发回归 NOT RUN。


## ADR-015 · 数据根先复制验证，再切换
- 日期：2026-11-06
- 决策：先 dry-run → `--copy` 到新根 → 校验 events/owner/diary → 再改 profile root。
- 理由：不能拿正在跑的角色直接 `mv`；事件流/owner cookie 一丢就难恢复。
- 现状：copy 完成、hash 一致；2026-11-06 15:57 已切换 root，旧根备份保留；QQ 真实回复回归 NOT RUN。
